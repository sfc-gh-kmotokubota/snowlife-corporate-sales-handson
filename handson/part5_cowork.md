# Part 5: 営業職員として CoWork を使う（15分）

> **このページの手順を上から順にコピペして進めれば完了します。**
> 「CoCo に送る」の枠は CoCo パネルに、「SQL」の枠は Workspaces の SQL ファイルに、「CoWork に送る」の枠は ai.snowflake.com のチャット欄に、そのまま貼り付けてください（枠の右上のボタンでコピーできます）。

## このパートでやること

ここまでは管理者（ACCOUNTADMIN）として作業してきました。
最後に、**東京第一法人営業部の営業職員** の権限で CoWork を使い、次の2点を確かめます。

1. 営業職員が普段の言葉で質問して、意図した回答が返るか
2. 担当外の支社の顧客データが返らないか（行アクセスポリシー）

---

## 5-1. 仕組みを確認する（3分）

setup.sql で、次の設定を済ませてあります。

| 設定 | 内容 |
|---|---|
| ロール `SNOWLIFE_SALES_REP_T01` | 東京第一法人営業部（T01）の営業職員ロール |
| 行アクセスポリシー `SECURITY.RAP_BY_BRANCH` | 取引先・商談・活動・既契約の4テーブルに付与。営業職員ロールでは担当支社の行だけが見える |

CoWork と Cortex Agent は、**ユーザーのデフォルトロール**の権限で動きます（画面で選んでいるロールではありません）。
そこで、自分のデフォルトロールを一時的に営業職員ロールに切り替えて確認します。

> **なぜ別ユーザーを作らないのか**
> 新しく作ったパスワードユーザーは、初回ログイン時に多要素認証（MFA）の登録が必要になる場合があり、時間内に終わらないためです。
> 本番では、営業職員一人ひとりのユーザーにデフォルトロールを設定し、SSO でログインする運用になります。

---

## 5-2. デフォルトロールを営業職員ロールに切り替える（2分）

SQL ファイルで実行します。

**SQL**

```sql
USE ROLE ACCOUNTADMIN;
-- 自分のデフォルトロールを営業職員ロールにする
EXECUTE IMMEDIATE $$
BEGIN
    EXECUTE IMMEDIATE 'ALTER USER "' || CURRENT_USER() || '" SET DEFAULT_ROLE = SNOWLIFE_SALES_REP_T01';
    RETURN 'デフォルトロールを SNOWLIFE_SALES_REP_T01 にしました';
END;
$$;
```

## 5-3. 営業職員として質問する（7分）

1. [ai.snowflake.com](https://ai.snowflake.com) を**新しいタブで開き直す**（CoWork はログイン時にデフォルトロールでセッションを始めます）
2. Agent に **法人営業アシスタント（B: 意味づけあり）** を選ぶ
3. 次の質問を順に送る

**CoWork に送る**

```
私の担当支社で、進行中のAランク商談の見込み金額合計はいくら？
```

```
進行中の商談がある取引先を支社別に一覧にして
```

```
KDDIの訪問準備をして
```

```
トヨタ自動車の既契約を教えて
```

確認するポイント:

| 質問 | 期待される結果 |
|---|---|
| 支社別の一覧 | **東京第一法人営業部だけ**が返る（管理者のロールで同じ質問をすると4支社が返ります） |
| KDDI の訪問準備 | KDDI は東京第一の担当なので、スキルが動いてブリーフィングが返る |
| トヨタ自動車の既契約 | トヨタは中部法人営業部の担当なので、**既契約の数値（構造化データ）は返らない**。ただし面談メモ検索の結果にトヨタの面談が出てくる場合がある（理由は 5-5） |

## 5-4. デフォルトロールを元に戻す（1分）

**必ず実行してください。** 戻さないと、以降の Snowsight 操作が営業職員の権限になります。

**SQL**

```sql
USE ROLE ACCOUNTADMIN;
EXECUTE IMMEDIATE $$
BEGIN
    EXECUTE IMMEDIATE 'ALTER USER "' || CURRENT_USER() || '" SET DEFAULT_ROLE = ACCOUNTADMIN';
    RETURN 'デフォルトロールを ACCOUNTADMIN に戻しました';
END;
$$;
```

## 5-5. 振り返り（2分）

> **ご提案に向けて押さえておきたい注意点**
> 行アクセスポリシーは、**Cortex Analyst（セマンティックビュー経由の SQL）** の結果には効きます。
> 一方、**Cortex Search** はサービスの所有者の権限で検索するため、元テーブルの行アクセスポリシーは検索結果に適用されません。
> このハンズオンでは面談メモ検索を全社共通にしていますが、本番で面談メモを支社ごとに見せ分ける場合は、
> 支社ごとに検索サービスを分ける、または検索時に支社でフィルタする設計が必要です。

ここまでで体験したこと:

| ご確認いただきたかったこと | ハンズオンで確かめたこと |
|---|---|
| データ投入 | setup.sql で CRM・PDF・他部署・外部データが1つのアカウントに集約される |
| セマンティックモデルの作成 | Semantic Studio と CoCo で、業務の言葉をデータに結びつけた |
| Agent の精度が上がるか | 同じ質問で、意味づけなしの Agent A と意味づけありの Agent B の回答を比べた |
| CoWork で意図した回答が取れるか | 営業職員の権限で、業務スキルに沿った回答と権限どおりの絞り込みを確認した |
